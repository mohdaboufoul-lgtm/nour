# Nour — Weekly regression scenario catalogue

Backlog for the weekly behavioural regression set (SPEC §13 "weekly behavioural regression tests on fixed scenarios", §16 definition of done, §18 "Weekly regression scenarios"). The seven shipped scenarios (SPEC §18, DESIGN §7.2) are not repeated here; every entry below is an addition, numbered S-01 onwards, grouped by the threat or rule it exercises.

## 0. Conventions

- Every scenario is driven through `nour.testing.harness.Harness` (DESIGN §3.21): `h = Harness.build(tmp_path, policy=<policy>)`, clock at Monday 2026-10-05 07:00 Asia/Dubai unless the setup moves it (`h.clock.set(...)`). Policies are the adversarial scripted models of DESIGN §3.9; `enqueue(tool_call(...))` means `h.fakes.models[PRIMARY].enqueue(ModelResponse(tool_calls=[tool_call(...)]))`, i.e. one scripted proposal on top of `SanePolicy`.
- "Tier" is the `TierDecision.tier` the gate computes (never the model's claim); `refused:<CODE>` is a `RefusalCode`, `readback` is `readback_required`, `deferred` is `deferred_until`.
- "Log entry" is the `closed` audit row (DESIGN §3.11): `ActionStatus` plus the `rules_hit` names of the TierResolver rules (DESIGN §3.16, numbered 1–13) or the refusal code. Rule names follow DESIGN §7.2 (`found_instructions`, `high_impact_no_passphrase`, `ask_every_time`, `default_new_category`, `new_counterpart`, `outreach_window`, `always_K`, `spend_band:<A|N|K>`, `freeze:<scope>`, `dnc`, `readback`); `tests/unit/test_tiering.py` fixes the exact strings.
- "Owner message" names an `OwnerMessageKind` (DESIGN §3.17): NOTIFY, ALERT, BRIEF, READBACK, APPROVAL, QUOTE_INSTRUCTION, REPLY, AUDITOR; "second channel" means `h.fakes.second.alerts`/`requests`.
- Owner-thread texts marked `cmd_NNN` are taken verbatim from `tests/fixtures/arabic_commands.yaml`; `<PASSPHRASE>` is the harness passphrase passed as `passphrase=`. Every scenario also asserts `h.reader.verify_chain()`, `h.assert_no_leaks()` and `h.replay(day).first_divergence is None`, and reads as the §18 triple: expected tier, expected log entry, expected owner message.
- Refs cite SPEC (§) and DESIGN (D§) sections.
